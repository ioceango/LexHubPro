# BUG-004 注册邮箱约束、验证码邮件与密码可见性

| 项 | 内容 |

| 编号 | BUG-004 |
| 严重级别 | 严重 |
| 日期 | 2026-08-27 |
| 状态 | 已修复 |
| 确认 | 用户要求修复优化（视为 spec/plan 确认） |

## 2. 问题

1. 注册页仅依赖浏览器 `type=email`，没有明确的前端邮箱格式约束。
2. 注册不向可用邮箱发送验证码：邮件实现只有 console，compose 默认 `AUTH_REQUIRE_EMAIL_VERIFICATION=false`，不会发信。
3. 注册成功后提示含糊，失败与成功区分不明显。
4. 登录、注册密码框没有显示/隐藏按钮。

### 复现

1. 打开 `/register`，输入非法邮箱（如 `a@b`）仍可能提交。
2. 用真实邮箱注册，收件箱收不到验证码。
3. 提交后页面无明确成功/失败 toast。
4. 登录/注册密码框只能密文，无法点眼睛切换。

### 根因

- 前端未做 `isValidEmail` 前置校验。
- `ConsoleMailer` 只记日志；未配置 SMTP 时不投递。
- 注册响应文案粗粒度且页面未用 toast 区分成败。
- 密码框是原生 `type=password`，无可见性开关。

## 3. 期望

- 注册提交前校验邮箱格式（长度、`local@domain.tld`），非法不发请求。
- 配置了 SMTP 时向该邮箱发送 6 位验证码；用户在注册页输入验证码完成验证。
- 成功用明确成功提示（toast + 文案）；失败用错误提示。
- 登录与注册密码可切换明文/密文，默认密文。

## 4. 验收标准

| 编号 | 标准 |
|------|------|
| AC-01 | 非法邮箱（缺 `@`、连续点、过短/过长）不发注册请求，页面与 toast 提示格式错误 |
| AC-02 | 配置 SMTP 后，新邮箱注册会发出含 6 位数字验证码的邮件；未验证不可登录 |
| AC-03 | 正确验证码激活账号后可登录；错误验证码明确失败提示 |
| AC-04 | 注册成功与失败均有 toast 与页面文案，语义可区分 |
| AC-05 | 登录、注册密码框默认密文，可通过按钮切换明文，再次切换回密文 |
| AC-06 | 点击注册只发验证码，页面进入「输入验证码」；不得出现「注册成功」或跳转登录 |
| AC-07 | 验证码一致后才弹出「注册成功」并跳转登录页 |
| AC-08 | 注册仅接受 163 / Gmail（含 126.com、yeah.net）；Playwright 截图按 S01–S07 归档 |

## 5. 边界

- 重复邮箱仍返回同一成功文案，不发信（防枚举）。
- 无 SMTP 时不强制验证，文案改为「注册成功，请登录」。
- 验证码入库只存哈希，并与 `user_id` 绑定。
- 邮件发送在事务提交之后。
