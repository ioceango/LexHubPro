# BUG-001 修复方案

## 1. 修复思路

问题本质是「动态配置读取缺少容错」与「前端路由缺口」两点，均为最小范围修复，不触碰认证体系设计。

## 2. 分层落点

| 文件 | 改动 |
|------|------|
| 后端认证登出路由 | 前端地址改为容错解析：变量缺失或仍为未替换占位符时，回退为当前请求来源地址；签发方缺失与地址拼装异常均加兜底，保证始终返回可用跳转地址 |
| 前端路由装配 | 新增登出回跳路由 |
| 前端登出回跳页面 | 新增页面，展示登出成功提示，提供返回首页与重新登录入口，风格与站点主题一致 |

## 3. 配置读取约定

统一采用「带默认值的属性读取 + 占位符校验」方式，避免裸属性访问导致异常：

1. 读取配置项时提供默认值。
2. 命中未替换占位符格式时视为无效值。
3. 无效值时回退到请求来源地址。

该约定同步写入配置管理规范，后续所有动态配置读取一律遵循。

## 4. 禁改文件确认

本次改动不涉及后端核心目录、模型目录、应用入口、平台认证回调页与预览配置文件。

## 5. 任务拆分

1. 修复登出路由的配置容错与兜底逻辑。
2. 新增前端登出回跳页面。
3. 在前端路由中注册该页面。
4. 执行静态检查、lint 与 build 回归。

## 6. 风险与回滚

| 风险 | 应对 |
|------|------|
| 回退地址取值不符合预期 | 仅在配置无效时回退，正常配置行为不变 |
| 新增路由与既有路由冲突 | 使用独立路径，不覆盖既有路由 |

回滚方式：改动集中在登出路由与一个新增页面，可单独回退且不影响其他功能。

## 7. 测试策略

- 覆盖配置项的三种状态：正常值、缺失、未替换占位符。
- 前端 lint 与 build 回归。
- 手工走查登出全流程。
