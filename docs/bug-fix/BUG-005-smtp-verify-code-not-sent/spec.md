## 2. 问题

配置 `SMTP_PROVIDER=163` 后，注册页面提示验证码已发送，指定邮箱收不到。

### 复现

1. `.env` 填写 163 的 `SMTP_USER` / 授权码 / `SMTP_FROM`。
2. 用已注册过的 163 或 Gmail 再点注册。
3. 前端进入「输入验证码」，收件箱无新邮件。

### 根因

- 现场探测：容器到 `smtp.163.com:465` TLS 正常，`SmtpMailer.send` 成功，SMTP 本身可用。
- `POST /register` 日志为 `register attempt on existing email`：邮箱已在 `tb_user` 且为 `active`。
- `register_user` 在 `EmailAlreadyExistsError` 时直接 `return message, None`，**不签发验证码、不发信**（防枚举）。
- 前端只要 `verification_required=true` 就进入验证码页，造成「已发送」假象。

账号多半是 SMTP 切到 163 之前（Mailpit 或未强制验证）创建的。再注册同一邮箱不会走发信。

## 3. 期望

- 新邮箱注册：事务提交后经 163 SMTP 发送 6 位码。
- 已存在且非禁用：再次注册视为补发验证码（仍返回同一对外文案）。
- 发信失败时明确「验证码发送失败，请重新发送」，不得假装已发送。

## 4. 验收标准

| 编号 | 标准 |
|------|------|
| AC-01 | 新邮箱注册会调用 SMTP 发 6 位码 |
| AC-02 | 已存在 pending/active 账号再次注册会重新签发并发送验证码 |
| AC-03 | 禁用账号再次注册不发信，对外文案不变 |
| AC-04 | SMTP 连通失败时接口提示发送失败，日志不含授权码与完整邮件正文 |
