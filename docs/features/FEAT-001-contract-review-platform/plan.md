# FEAT-001 技术实现方案

## 1. 架构影响

前后端分离：前端 React 18 + TypeScript + Vite + shadcn/ui + Tailwind；后端 FastAPI + SQLAlchemy Async + PostgreSQL；认证、数据库、对象存储、AI 能力均由 Atoms Cloud 提供。

关键取舍：审查接口只做 AI 计算并返回结构化结果，落库由前端经 entities 完成，从而获得自动 user_id 隔离，同时避免数据库事务跨越慢速 AI 调用。

## 2. 分层落点

**后端**

| 文件 | 职责 |
|------|------|
| `routers/contract_review.py` | 入参校验、调用服务、异常映射为 HTTP 状态码 |
| `services/contract_review.py` | 合同文本提取 + 结构化审查编排 + 结果校验与归一化 |

**前端**

| 文件 | 职责 |
|------|------|
| `src/pages/Index.tsx` | 首页介绍与入口 |
| `src/pages/Review.tsx` | 上传、立场选择、进度展示、触发审查 |
| `src/pages/ReportDetail.tsx` | 报告结构化展示与复制/导出/下载 |
| `src/pages/History.tsx` | 统计概览与报告列表管理 |
| `src/lib/review.ts` | 报告字段解析、报告文本生成、下载链接解析 |
| `src/hooks` | 认证三态（loading / authenticated / anonymous） |
| `src/App.tsx` | 路由与布局装配 |

## 3. 数据库变更

| 表 | 关键字段 |
|----|----------|
| `contracts` | 文件名、合同类型、用户立场、对象键、上传时间 |
| `review_reports` | 关联合同、整体评分、风险条款 JSON、缺失条款 JSON、合规检查 JSON、关键条款 JSON |

风险/缺失/合规条目为只读展示数据，以 JSON 字符串存单列，不建独立表。

## 4. 对象存储

新建私有桶 `contracts`，仅持久化 object_key；下载时通过 SDK 换取临时链接，不存储过期 URL。

## 5. AI 编排

1. 合同文本提取：使用 PDF 分析能力获取全文条款。
2. 结构化审查：使用 `claude-opus-5`，以委托方立场输出 JSON 结构结果。
3. 容错：JSON 抽取 + 必填字段校验 + 一次修复重试；风险等级与合规状态做中英文与大小写归一化。

## 6. 设计模式

- 服务层采用编排式函数组合，提取与审查两阶段解耦，便于单独替换与测试。
- 前端报告解析集中在 `lib/review.ts`，页面只负责渲染，降低重复逻辑。

## 7. 任务拆分

1. 建表与建桶。
2. 生成品牌配图。
3. 后端审查服务与路由。
4. 前端设计系统（深色专业法务风格）。
5. 首页。
6. 上传审查页。
7. 报告详情页。
8. 历史记录页。
9. 路由、布局与认证三态。
10. lint / build 与页面渲染校验。

## 8. 风险与回滚

| 风险 | 应对 |
|------|------|
| AI 返回非法 JSON | 抽取 + 校验 + 一次修复重试 |
| 审查耗时过长 | 前端超时 600 秒并展示分阶段进度 |
| 大文件导致失败 | 前端前置校验大小与格式，超限直接拒绝 |

回滚方式：审查接口为新增接口，异常时前端保留上传态并提示重试，不影响其他页面。

## 9. 测试策略

- 静态检查：后端 `py_compile`，前端 `pnpm run lint`。
- 构建门禁：`pnpm run build`。
- 页面渲染校验：平台 UI 校验能力。
- AI 调用不做真实请求测试。
